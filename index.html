社区观察｜家庭和社区都一样：你没有退路，它们就使劲儿捏你

发表于 2026-09-20 08:55:38 更新于 2026-09-20 08:55:38 分类于 社区冲突 ， 家庭尸检

声明：本文提到的社区指的是河南省济源市龙潭花园。

2025年6月，我从社区走的时候，一圈邻居打探：她去哪里？
废话，去外地工作。

那一刻，好像从2025年3月到5月，我被骚扰、被围猎的那段日子，根本不存在一样。

先倒回去一点。2025年5月，我在家被讽刺没有工作。6月，我花了一周拿到面试，第二周就入职了。

上一篇我写过，家里在我没退路的时候，觉得我不值钱；我一要跑，忽然就值钱了。现在回头看，社区也一样。你没有退路，它就使劲儿捏你。

为什么这么像？

我的理解是，捏人靠的是依赖。你越依赖一个地方，它能捏你的地方就越多。我没工作、住在家里、每天生活在这个小区的时候，家和社区就是我唯一的选项，两边都能使劲儿。一旦我拿到外地的工作，有了别的选择，他们手里的筹码就一起缩水了。
（经济学家赫希曼在《退出、呼吁与忠诚》里讲过类似的事：一个人能不能被认真对待，很大程度上取决于他有没有退出的可能。）

而且家庭和社区本来就不是两个独立的系统。我妈爹本身就是社区的一部分，用的是同一套本地逻辑，家里的叙事还会直接流进社区。同一批人，同一套规矩，捏人的方式自然长得一样。

至于邻居那句“她去哪里”，恰好印证了我之前的猜想：他们攻击的从来不是我这个人，而是那个靶位。我一走，靶位空了，“坏人”的身份也跟着蒸发，剩下的只是一个“去外地工作的人”，成了普通谈资。

当然也得承认，人一走远，每天的摩擦，比如噪音、窗户、钱，也就跟着没了。态度变好，有一部分是距离本身带来的，不全是算计。

但接下来的事，光靠距离就不好解释了。

2025年9月，我搬回来。同一个月，有人造谣我是妓女，我的电动车被扔了屎。

我回到了那个跑不掉的位置，靶位又有人了。

后来我开始报警、取证、录音、记录，骚扰才有所收敛。

现在我人还在这里，但工作不在本地找，不靠他们的人际关系吃饭，朋友和人际关系也多在沿海那边。退出不一定是搬走，也可以是不再依赖。

所以他们手里还剩什么？只剩噪音，和一扇不许关的窗户。

家庭尸检｜我没退路的时候不值钱，一要跑，忽然就值钱了

发表于 2026-09-20 07:05:39 更新于 2026-09-20 07:05:39 分类于 家庭尸检

前情见上一篇：《写写一扇窗户，怎么成为家庭冲突外溢到社区的东西？》

2025年春天，我一边应付社区的骚扰，一边应付家里妈爹的辱骂和施压。就在这种内外交困的环境里，我开始做梦，梦见我死了。
醒来我想：不行，这环境不能待了。

2025年5月，我准备跑路，但还是幻想能不能继续呆在社区，6月投简历找工作。本来打算做技术，后来为了快点走，干回了老本行剪辑。
我还没开始找的时候，我妈嘲笑我：你不是说要找嘛？什么公司会要你？
一周之后，我拿到面试，去了郑州。

面试那趟，我爹陪着我，一起住青旅。他一见到老板娘，就大肆宣传我是来面试的。我立刻截断他的话，让他别再说了。

面试那几天，我跟GPT聊职业策略，我爹在一边骂：你妈逼的～
嗯，到底是骂AI还是骂我呢？我完全不懂。但GPT至少不会把我的事拿去跟邻居讲，不会把我做成靶子给社区攻击，还能给我讲面试注意事项。比我爹靠谱多了。

我出门面试，我爹特别得意。得意什么呢？得意有东西跟邻居们夸口了，有新谈资了。

他走之前还跟我说，怕我一个人在外地被人欺负。
我：你这个大嘴巴，才是我的风险泄漏源头之一。你嘴巴闭紧点，我反而安全呢。（笑）

把我的隐私拿出去当谈资，最后让我被社区不断攻击，这事他们在社区已经干过一遍了。来到外地，又复制一遍。

我搬到外地之后，之前一直喊我滚蛋的妈爹，主动联系我，问我住在哪里，要来看我。
哎？很神奇。我在家的时候，他们恨不得跟社区一起把我生吞活剥了。我一搬走，忽然就值钱了？
其实不是我值钱。我没有退路的时候，不值钱；我要跑了，不需要他们，也不依赖他们了，这才值钱。

后来我爹来看我，带了两个烂掉的西瓜，五瓶AD钙。
我给他买了墨鱼饺子，做了蒸南瓜、炒鸡肉、鸡腿、花生，又买了蛋糕和牛奶。
他嘴上说：饺子怎么是黑的？然后一个不落地吃完了。
我：你爱吃就吃，装什么客气。
还得我陪着他费劲儿地演。无语。

哎，神奇，这个时候他好像又变回了偶尔会关心我的爹。（笑）

有时候也想，还好是这几年没工作的时候，我才看清妈爹的这副嘴脸。我要是一路顺下去，没经历过这种坎坷，我可能一辈子都在想，我妈爹真的爱我呢。

家庭尸检｜写写一扇窗户，怎么成为家庭冲突外溢到社区的东西？

发表于 2026-09-20 05:05:36 更新于 2026-09-20 05:05:36 分类于 家庭尸检 ， 社区冲突

声明：本文提到的社区指的是河南省济源市龙潭花园。

我跟社区的冲突由来已久，主要是噪音问题。但有一个神奇的地方：我妈爹禁止我关卧室窗户。理由是：关窗也隔绝不了噪音；房间有甲醛，关窗对健康不利。

前几天我买了甲醛试剂盒，测试结果显示正常。我拿给妈爹看：这可以关窗了吧？
他们没接茬，继续复读之前的几句话：不许关窗，为了你的健康，关窗对健康不利。

刮风天的时候，他们会主动让我关窗户。这时候又不说关窗不健康了。

我关上窗户，他们会从外侧用木棍把窗户搂开。

2026年5月，他们不仅强制开我窗户，还强行闯进我房间。我挡住门，报警。警察训诫我父母：孩子不是你们的私产。
于是他们不再强闯房间，改成开窗户。毕竟，我因为他们强制开窗户报警，似乎显得小题大做？

一扇窗户而已，为什么要如此大费周章？

一开始，社区冲突还没有的时候，窗户是妈爹做家庭控制的手段。不是窗户很重要，而是他们觉得我得听话，这个家是他们说了算的感觉很重要。

我跟妈爹的矛盾，主要来自他们希望我立刻去工作，什么烂活都可以，只要能拿到钱。我在博客写他们，他们很不高兴；我跟别人聊他们的烂事儿，他们也很不高兴。他们对外的叙事是：我啃老，暴脾气，天天不知道在干什么。

2025年3、4月间，我刚换了手机、手表和电脑。妈爹想知道我手里有多少钱，我死活不说，也不给他们花。正好也是这个时候，社区开始围猎我。这个时间窗口很巧。围猎过程中，妈爹什么都没做，一边主动跟我切割，一边不断对外说「之瑞多么多么过分」。

家里骂我白眼狼、啃老。社区拿着我跟父母的冲突，合理化骚扰。我跟社区冲突，骂他们管得宽；妈爹反过来指责我：你要是好，别人干嘛对你指指点点？
我内心OS：不是您二老给人家提供的我的隐私吗？让人有指责我的材料。

我的猜想是：我被妈爹做成了可以攻击的靶子，他们给社区闲人提供了攻击我的道德弹药，然后社区里对我早有不满的人趁势而上，一路持续到2025年9月我搬回来，达到顶峰。后来我明确表示要报警，开始取证、录音、记录，骚扰才有所收敛。

这时候关窗户、戴耳机，隔离噪音和外部刺激，是很有必要的手段。但被我妈爹拒绝了。

没了这扇窗户，社区的骚扰透过窗户传进来，我的动静也透过窗户传出去。我跟妈爹的冲突，同样顺着窗户，成了闲人八卦的素材。

我之前猜想，自己被当成了取乐的靶子。当靶子需要什么？需要反应可见。你骚扰一个人，对方没反应，骚扰的乐趣就下降了，因为对方切断了反馈，骚扰自己就进行不下去了。
窗户不许关，楼下随便折腾，我的即时反应立刻可见。你要是骚扰我的人，你也会觉得乐趣多多。（笑）

窗户为什么对他们这么重要？因为这是唯一还能拿捏我的地方了。

工作，我不在本地找，不靠他们的人际关系吃饭。朋友，不跟他们交。人际关系，也多在沿海那边。传统上用来规训一个人的手段，比如说你不好，给你的雇主施压，让你在本地活不下去，对我来说都没用。何况本地也真没有AI相关的工作（笑），没有人是我的潜在雇主。

那么唯一能影响我的，就是健康和睡觉。睡觉，就是噪音。又回到了这扇窗户。

2026年5月我检查身体，空腹血糖14.53，LDL-C 4.24，情况非常不妙。我当然需要规律作息。可长期的家庭和社区冲突，持续不断的小规模骚扰加噪音，再加上不许关窗，睡眠和作息当然烂。烂完之后，血糖和代谢出问题，几乎是毫不费力就能想到的事。

后来经过我努力控制，当然期间骚扰也没停，现在家用血糖仪晨起空腹5.5，上个月复查LDL-C 2.5。

血糖的事，社区的人也都知道。我妈爹一个不漏，全说完了。

社区观察｜不是这个地方碰巧坏人多，而是一个靠共同嘲弄来维持秩序的群体，总得不断制造新的坏人

发表于 2026-09-20 04:40:06 更新于 2026-09-20 04:40:06 分类于 社区冲突

声明：本文所指社区为河南省济源市龙潭花园小区。

去年9月，有人造谣我是妓女。我的电动车被扔了屎。楼下大妈骂我不要脸。
今年4月，楼下小孩在窗台上辱骂我。
5月我出门逛公园，一个穿紫色衬衫的中年男人骂我是傻逼。我举起手机准备拍摄，他立刻逃走。

这些人，我甚至都根本不认识。
围猎最严重的时候，我从不认识的小孩身边经过，都会被骂。我做了什么呢？不就是过自己的生活嘛？

来写写为什么这一年多我会被持续围猎，一点机制猜想。

不是我多么越界，而是这个社区需要一个人当「坏人」，被捉弄取乐，而群体会持续地、自发地奖励这种行为。

生活里本来就有怨气、无聊、挫败和互相监视 → 某个人因为显眼、不同、已有冲突或反应可见，被证明“拿她开涮成本不高” → 起哄能获得同伴反馈 → 行为不断被强化 → 最后形成一个稳定的公共靶位。

所以这一年多的围猎、造谣和骚扰，我承担的其实就是这个角色。

这个社区需要一个被定义为「坏人」的人，攻击这个坏人，就成了一种「娱乐、结盟、确认群体边界、转移内部矛盾、宣泄攻击性」的手段。为了证明攻击的正当性，他们还会不断炮制关于我的谣言。

他们攻击我，并不只是私人恩怨，还有一层，就是「对这人可以越界」。那么以后我搬走、跑路、换工作，他们随便拿社区里另一个人开涮，这一套信手拈来，毫不费力就能继续复制。

所以不是这个地方碰巧坏人多，而是一个靠共同嘲弄来维持秩序的群体，总得不断制造新的坏人。

声明：本社区指的是中国河南省济源市济渎大街和太行北路交叉口的小区龙潭花园。

本来夜里3点起夜。
醒来之后还没开灯，楼下一声电驴响起。滴滴滴。我起来了，妈爹也已经起来准备摆摊。
二位没多久就回去了。

我躺回床上。凌晨四点左右，又被楼下的汽车喇叭吵醒。
不得不再度起来，写博客。

虽然我觉得写博客写社区噪音是件极其愚蠢的事情（笑）。但你看，夜里总有几个人喜欢摁喇叭，于是凌晨我就醒了，睡不回去，闲着也是闲着。

我现在对社区和老周老袁整个集合体，完全没有信任可言。

昨天下午，社区一群小孩在楼下大喊：龙潭花园没人管管嘛？
我在楼上内心os：哈哈哈哈，有人管的话，我还需要天天写社区噪音挂博客嘛？

如果一个人被围着起哄、越界的时候，周围人也乐于添一把火，那最好别默认这套规则永远只会用在别人身上。

就像最近，老袁被自媒体带的情绪激动，跟我讲，二战的日本人真的不好，杀他们属于是降魔。
我：你最好期待自己一辈子不会变成日本人。（笑）
老袁：我怎么会是日本人？
我：哎，鹿也不知道，自己会被说是马呀。

这地方的人，都想着给别人套个笼子，然后又都被别人套着笼子。

社区噪音｜为什么真正扰民的没人管，不扰民的私人生活却人人想管？

发表于 2026-09-18 00:10:20 更新于 2026-09-18 00:10:20 分类于 社区噪音 ， 龙潭花园

先写在前面：本博客写的社区，如果没有明确指明是哪个社区，那就默认是「中国河南省济源市济渎大街和太行北路交叉口的小区龙潭花园」。

本博客好久没写过社区了。之前因为社区的噪音+围猎问题写过很多篇博客。本来以为互相忍忍就过去了。
没想到今天预期被打破了。（笑）。不然我也不会深夜坐在这里写博客了。

本来今夜准备入睡，22点36分躺下准备睡觉。结果楼上开始跟地板有仇，碰碰碰地板开始哀嚎起来。我特别关切楼上那一户家里的地板，天天被这么砸，还好吗？（这次不在博客点是哪一户了，如果你们家地板受损严重，我为了地板发声，可能下一次就直接说是哪一户了）。
楼下路过的人驻足闲聊。我非常汗颜，在楼梯口驻足闲聊，扰民不说，就不怕自己隐私被楼上听到吗？反正我是听的清清楚楚。

于是两下三下，本人睡眠窗口被打断了。只好夜里来写博客，盘一盘这个社区最近的噪音了。

先说楼上的噪音，作为楼下的受害者，基本都是夜里10点半～11点半的时候开始响起来。我本来是21点～22点睡觉的习惯。因为这个时间段社区来往人多，噪音大。不得不推迟到23点入睡。结果这也不行，楼上总能准时到在我入睡窗口给地板上酷刑。
花样还挺多——桌腿酷刑：拉桌子拉家具，桌腿摩擦滋啦滋啦的，跟地板被剥皮了一样；大锤酷刑：猛烈砸击地板，这家砸地板的最高纪录是90dB+，大概是5月还是6月的时候，Apple Watch环境声里，一个90dB+的峰值噪音，刚好伴随着楼上传来的撞击声。当然，手表只能记录我这个位置的环境声，不能精确定位声源——但对我来说，已经够明显了。

我在四五月份写过博客吐槽社区的小孩出口成脏，脏话连篇（公共场合）。今天又遇到了。我在窗台写代码，楼下小孩开始满嘴「傻逼」「操你妈的」之类的。脏话声连绵不绝～
我不要求小孩子说话时刻文明得像教科书，偶尔一句脏话也不是天大的事。问题是，公共区域里连续高声骂人，而且不是第一次了。
我挺好奇的，这社区隔壁就是学校，我以为挨着学校的社区好歹小学生的素质也高一点？结果本人亲历居然是满嘴脏话。令人百思不得其解。

上一次写社区是8月，现在刚九月，没有一个月，社区的噪音就再度复发，我不得不深夜写博客来吐槽。
我挺好奇的，这个社区的噪音/素质差的问题反反复复——深夜22点半了，别楼下聊天，难道很难做到？23点半的时候，别砸地板，难道很难做到？公共场合，别出口成脏而且别让小孩子在人多车多的地方乱跑，很难做到？
这些要求算不上苛刻。不是要求整个社区进入绝对静音，也不是要求所有人围着我转。只是集体居住最基本的一点边界感：你的生活可以有声音，但不要持续把明显的成本转嫁给别人。
平均一个月的稳定期都撑不过，让我如何相信社区可以让我安心住下去呢？

为了这些毫无意义的事情，我在这边写博客，吐槽他们。我觉得很烦，一个社区的低素质和低治理，变成了我用肉身和时间来给他们买单。凭什么？
凭什么这个社区的某些人要把自己的低素质变成转嫁给其他人的成本？凭什么这个社区的某些人只有在我写博客吐槽之后才会安静？凭什么这个社区的某些人只有在怕我投诉，找规则，曝光的时候安静？

说到底，外部成本就是这样产生的：行为发生在一个人身上，代价却由另一个人承担。对制造噪音的人来说，可能只是拖一次桌子、聊十分钟天、砸几下东西。对被打断睡眠的人来说，却可能意味着一次入睡失败，后面几个小时都睡不好。

为了获得一点本来应该很普通的安静，我需要付出多少额外的注意力？记录噪音，写博客，投诉，查规则，判断声音来源，考虑怎样沟通，甚至调整自己的作息。
本来我可以拿这些时间写技术博客、准备面试、写代码，或者直接睡觉。结果花在了”晚上十点以后能不能稍微安静一点”这种事情上。
（我本来血糖高，需要规律休息。但因为社区噪音，规律休息基本做不到，这就是肉身来抗社区的低素质人转嫁的成本）。

社区很敏感于声誉风控，怎么说呢？就是我写博客挂社区，社区就安静。不写博客挂社区，社区就继续。本质上，社区安静并非真的尊重我的需求，而是当我把外部成本推高之后，不得不暂时安静而已。
但我又很好奇，22点～6点之间，尽量不扰民，尽量安静，难道不是集体居住的默认该遵守的规则吗？怎么还要我天天挂博客写社区，才能安静呢？

噪音的问题还没完，再说说这个社区的人际氛围。

最近特别好笑，骚扰了我将近一年多的社区里，一些我不认识的人，电梯里问我你几楼的？坐不坐电梯？我无视走开。结果被说是「看不起人」。
我觉得特别好笑。

围猎我的时候，到底是谁看不起谁？非得我去写博客吐槽噪音的时候，才安静，这到底是谁看不起谁？
然后一朝说两句好话，我不接，就又开始了，讲我「看不起人」。那么我请问，让我不计前嫌，立刻信任这个社区的人，是不是也有点看不起我呢？难道我自己没有自主权决定要不要亲近谁，远离谁吗？难道之前的种种，我被辱骂，造谣，威胁，骚扰的种种，因为2句好话，就让我什么都不计较，立刻信任。
别人可以觉得我冷淡。但不能因为忽然说了两句正常的话，就要求我立刻恢复信任。更不能把”不愿意重新亲近”直接解读成”看不起人”。
好，哪怕我真的信社区可以变好，但很好玩，4月我吐槽小孩在我窗台下出口成脏，9月又老毛病复发。让人信任是有前提的，前提是稳定的可预期的表现。而不是前面闹腾了很久，忽然正常了一阵，立刻要人去忘记过去的事儿，去融入社区。这岂不是强人所难？

8月的时候，凌晨3点闹腾到下午16点，我被迫骂人让闲人离开。结果呢？结果一切照旧而已。

再说一个我观察很久的反差。

这个社区里，有些真正影响公共生活质量的行为，大家似乎非常能忍。这些事情不是每个人都在做，也不能说整个社区所有人都赞同。但从我的个人体验来看，它们往往缺乏持续、明确的约束。

之前本博客写的《痰道十八式》就是吐槽社区随地吐痰。写之前，本人出门一趟，吐痰声音不绝于耳。出门取快递的不到300米的路上，几乎每次必遇到1～2个吐痰的。
哎，吐痰呢？这是社区默许的。没人管。
噪音呢？这是社区默许的，没人管。

那社区管什么呢？
管你出门穿不穿胸罩。管你在家是啃老还是进工厂上班。管你是不是听父母的话。管你是不是周末睡觉到天亮。
（嗯，这里说的管，并非物业是否管理，而是社区的潜规则，也就是什么人被当作应该管，什么事情被当作可以议论）。

你看，放到一起就非常滑稽了——

没人管的： 随地吐痰。出口成脏。深夜砸地板。造谣围猎邻居。
抢着管的： 女孩子出门穿没穿胸罩。是不是啃老。是不是不听话。是不是周末睡到天亮。

前者可能真实地影响别人的生活质量，视而不见；后者很多时候根本不影响任何人，偏偏人人有话说。

两相对比，谁是默认可以被管理的，谁是不能碰的。默认可以被管理的，哪怕做事根本影响不到别人，也会被议论，嘲讽，起哄，围猎。默认觉得自己可以管别人的，哪怕是噪音，造谣，围猎别人，随地吐痰，出口成脏，也被视而不见。

写到这里我发现，自己真正在意的东西已经变了。

以前我可能还想过，这个社区的人怎么看我，是不是误会我，能不能互相理解。

现在我更关心的是：这里的公共规则是否稳定？扰民行为有没有边界？私人生活能不能不被随意干涉？出了问题，处理成本是不是永远要受影响的人自己扛？

一个地方适不适合长期住下去，对我来说越来越取决于这些。不是大家见面有没有笑脸，也不是偶尔两句好话。

而是你能不能稳定地预测：晚上睡觉时，大概率不会突然有人开始砸地板。下楼取个快递，不需要一路听人吐痰。不和陌生人聊天，也不会立刻被解读成”看不起人”。自己的衣服、工作、作息，不会变成别人理所当然可以讨论的话题。

这些事情单独看都很小。但长期叠加起来，就是居住体验本身。

我不要求一个社区完美，也不要求所有人都高素质、都互相喜欢。我只希望一件很普通的事情：

影响别人的事情，有一点边界。

不影响别人的事情，少一点指手画脚。

如果连这一点都需要反复争取，那我对这个社区保持距离，也就不是什么很难理解的事情了。

TL;DR

为啥单测全绿，集成测试还是挂了？因为单测验证的是对象行为，这次坏的是 Spring application wiring。

最后查出来是多 Provider 重构之后，IT 手写的 @Import 漏了 provider-neutral 公共配置；生产 wiring 完好。

修复方式：只给 IT 补 import LlmCommonConfiguration，生产代码 0 改动。

总结：测试上下文和生产上下文并不天然等价。

症状

IT 稳定 5/5 失败，单独跑也挂，所以不是 flaky；

报错是 UnsatisfiedDependencyException 包了 NoSuchBeanDefinitionException。

此时单测全绿，mvn test 全绿。

是 production wiring 还是 test wiring？

一开始先不预设是测试的问题，先追完整的依赖链条，看是 production wiring 还是 test wiring？

有 2 个假设：

  • 假设 1：production-environment context 缺 bean 导致报错。
  • 假设 2：production context 正常，但集成测试配置缺 bean，导致测试失败。

于是我设计了两个 case，验证这两个假设：

  • caseA 验证应用在没有开启 AI Explanation 的时候，能正常启动。说明 deterministic core 没有被 AI 配置污染。但不能排除 AI-enabled production wiring 有问题。
  • caseB 验证开启 AI Explanation 的时候，当前真实调用链能成功装配。如果 production-equivalent context 本身也缺 bean，那这就是 production wiring defect，假设 1 成立。反之则是假设 2 成立。

于是我给 Codex 下指令，让它执行命令：

  1. 先追踪完整依赖链条，读取完整的 Spring context failure，明确 constructor 依赖哪个 bean，最终要求 explanationPromptFactory，为什么当前的 ApplicationContext 没有注册它。先汇报实际的 dependency chain，不先改代码。
  2. 分别验证 caseA 和 caseB：不用真实 API key，不调用真实互联网，用测试配置或 fake provider。如果 production-equivalent context 本身也缺 bean，那就是 production wiring defect，不许只修测试。
  3. 如果仅 TestConfiguration 缺乏 bean，也就是 production context 正常，但是 RefundCaseExplanationControllerIT 因为自己的 @Import/@TestConfiguration 替换 provider 之后漏掉了 deterministic prompt factory，则只修装配测试。优先注册真实的 explanationPromptFactory，因为 prompt factory 是纯确定性组件，没必要 mock。不许为了让 context 绿了就把
    • production dependency 改成 optional
    • 使用 @Autowired(required=false)
    • 给整个 application 加宽泛的 component scan
    • mock 掉 RefundCaseExplanationService
    • mock 掉 deterministic diagnosis chain

因为测试层级不同。

为什么当初会手写 @Import

回头看这个 bug，容易得出”手写 @Import 是坏习惯”的结论。但当初写成那样，动机是完全正当的：这个 IT 要验证 explanation pipeline，就必须指定用哪个 provider、必须不打付费 API、还得让上下文起得快一点。

目标没错，错的是实现方式。为了隔离外部依赖，我把整个 dependency graph 重建了一遍，而不是在边界上替换。

隔离外部依赖，和重建依赖图，是两件事。前者只需要换掉边界，后者会复制一份必然过期的生产拓扑。

这里其实有三种做法，不是两种。之所以要把第二种也摆出来，是因为正是它的缺点，逼着大家去选第一种：

A. 手写窄 @Import B. 完整生产 context + 真外部依赖 C. 生产装配入口 + 只 fake 边界
真实性 低。装的是测试自己裁剪的拓扑，不是生产拓扑 高，但代价是真连供应商 高。拓扑与生产同源，只有边界被替换
外部依赖 已隔离 需要真实 API key，会产生费用 已隔离，fake server 在本机
漂移风险 高。生产重构后测试不会自动跟进 无。生产变了测试自动跟着变 无。同一个装配入口，改一处两边都变
架构重构时要改几处 每个手写 IT 各改一处 0 1 处（装配入口）
启动速度 待测 待测 待测

本次踩的就是 A 的漂移风险那一格，而且证据是现成的：同一个 37caac9 revision 上，production 扫描根能把 LLM 子图完整装起来，手写窄上下文却缺 Bean——这就是 A 和 C 的差距被量出来的样子。

B 在现实里基本不可用，所以真正的选择从来不是「隔离」还是「真实」，而是「在哪一层做隔离」。A 在配置层做，于是复制了拓扑；C 在边界层做，拓扑留给生产自己算。

防止复发

第一条是原则：集成测试不要复制 production dependency graph。让 production 自己构造 dependency graph，测试只替换 side-effect boundary。

具体做法：测试不再手挑 configuration 类，改 import 一个生产测试共用的 LLM 装配入口，只在 provider/网络边界做替换。

回归测试：加 wiring regression test，覆盖 AI disabled context 能起，以及 explanation context 下 PromptFactory 有且只有一个。

这条其实已经有现成的原型了。上面 caseB 用的 HistoricalProductionLlmScanTest，就是一个以 production 扫描根启动、断言 Bean 唯一的最小上下文测试，只不过它只活在 37caac9 的隔离快照里，删掉就没了。把它固化进仓库（换个名字，比如 ProductionLlmWiringTest），下次再抽公共层，先红的就是它，而不是等 Failsafe 跑到 Controller IT。一个临时的排查脚手架，顺手就能变成常驻的护栏。

流程上，mvn test 不跑 IT，确实是漏洞。IT 红了多久？最早是从多 SDK 重构、公共配置抽离后开始失效；真正首次被完整 verify 捕获是在后续 strict-schema 修复阶段。也就是从 37caac9 持续到 4e3aca8，最后用两行测试 wiring 修复结束。

日常和 CI 到底应该跑什么？日常：targeted tests / mvn test；pre-merge CI：mvn clean verify；可选 nightly：clean verify + repeated flaky-sensitive IT。
