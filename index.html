日常记录｜「认清现实」很多时候只是让你接受别人替你规定的上限

发表于 2026-09-10 20:32:25 更新于 2026-09-10 21:20:43 分类于 日常记录

我最近写代码的时候，我妈对我说，有时候你就是无法认清现实。
然后劝告我：你上班一个月5千，你爹一个月5千，我一个月5千，你弟一个月5千，咱家就一个月入2万，多好呀。

我其实特别好奇？如果Agent不是现实，那5千块去富士康就是现实吗？

我想起来，我小时候，一年级，我跟不上，我没有认可「我就是很差，我学习不好」这个很容易被贴给我的标签。
没人帮我找补习班，也没有人鼓励我，我就慢慢的咬着一口气，不觉得自己也就只能不及格，慢慢的放学把我觉得很难的东西一点一点啃下来。
到了二年级，我成绩就好了。

这个不接受外界贴给我的「你就这样了」「接受现实」「你就不聪明」「你没有天分」的标签。

后续我高考的时候，成绩也有一阵子不好，模拟考考了590分，我当时心里想的是，只是这一次失败，我可以慢慢调整自己。
虽然当时我妈跟我说：你爹对你很是失望。除了这一句，没了。
我妈则四处烧香拜佛。
其余提升成绩的事情，他们做了多少呢？0。

最后成绩不错，我妈四处说，为了我高考，给我花了很多钱。但那些钱大多都给神婆供奉了，并没有真的流到我身上。
这又是一个案例，我班主任当时说我考的好是「走运」，我妈只烧香，我爹说「对你很失望」。真正改变结果的还是我自己。
如果当时我告诉自己，我就这样了，算了吧。班主任说我走运，也许我真的是走运呢？我爹说对我失望，也许是真的呢？我妈说我自己不行，我需要神婆的帮助，也许我真的不行吧？如果这么想，我大概会一路差下去。
正是不接受周围环境给我定义的「你是什么样的」我后续才有心理空间慢慢改善自己的成绩。

后续毕业，我本地找工作，月薪1500块的剪辑小公司，月休息4天，我干了一个月辞职。
我妈表示：你怎么辞职了？
我：那并非能长久干的工作。
我妈：那也比家里蹲好。
我：我要转代码。

后续我就真写代码去了。
如果我接受了我妈的版本「我就是只能干1500块一个月的流水线剪辑，我大概这辈子也没机会去写代码」。

在我写代码期间，我爹说我：「你堂姐比你强多了」。
我：她也是剪辑，一个月4千，吃吃花花，一个月能攒下1000块就不赖了。
我爹：「那她至少也有钱，4千块，你说的轻巧，你先给我赚回来再说」。

现在AI来也～
她们公司任务量三年之间翻了好几倍，但工资没涨多少。
而且裁员较多。
加班也严重。

如果我接受了我爹当时对我的定义，堂姐的现状就是我的天花板。
也许我现在就在哪个剪辑小公司，因为AI来临+就业环境遇冷，被双重冲击。

后续我写代码。培训班老师吐槽我写的很差。（笑）。
当然现在我看当时项目，我写的确实差，但项目本身的源码，最近我看，事务边界都没有捋清楚。不变量，状态机，也不大清晰。

如果我当时接受培训班老师对我的定义，我大概现在早放弃编程了。
毕竟，我写的很差。

后续到了Agent，如果我想着「我只是很普通的Java后端」，这不是我能碰的。
我大概不会2天写完Agent项目的V0版本。也不会认真规划Agent项目的演进。

你看，当我接受外界对我是谁的定义的时候，我大概总是那个「不配」的人。
但真的做了，那些事情并非需要「你配」才能做。

所以，我生活里让我做对选择的因素，其实一直很稳定：我很少把别人对我当前状态的判断，当成对我最终能力的判断。
而真正容易让我错过正确选择的，也恰恰是另一种东西：有人会把眼前最容易得到、最安全、最熟悉的选项叫做“现实”，再把暂时没有做到的事情叫做“你不配”。
前者是反馈，后者是在替人封死搜索空间。
我现在更愿意接受反馈，但拒绝接受判词。

所以「配不配」是别人嘴里的，「能不能做」是掌握在自己手里的。

日常记录｜项目的门禁测试失败了，原因是啥呢？是iCloud同步工作目录，导致出现随机的NoClassDefFoundError

发表于 2026-09-10 11:46:35 更新于 2026-09-10 12:18:19 分类于 日常记录

如题～
执行集成测试的时候，出现了5个Errors。几个类找不到。

直接原因是Failsafe JVM 类加载异常。后续排查的时候，没有发现ExceptionInInitializerError，或者Could not initialize class，所以不是静态初始化失败。
然后检查Failsafe effective configuration，同样的配置再隔离目录运行稳定。所以不大像是配置问题。
再检查仓库有无自删 build output，没有发现脚本或者测试启动了子maven，或者清理了target/classes或者target/test-classes。或者修改了全局的classpath，或者动态删除编译产物，或者操纵URLClassLoader。
再检查 Suspect.class的完整性。后续四个找不到的文件mtime都是10:37:19，但是ctime分散在10:39～10:40，隔离副本重新编译出来的size，SHA-256与原目录相同，说明源码和编译结果本身正常。
然后检查数字后缀/冲突生成物。没有发现数字后缀或者生成物冲突。而且target/classes和target/test-classes目录中的没有symlink，不可读文件，dataless文件。
后续检查到项目目录，在 ~/Documents下，它底层不是symlink，而是本地APFS，file-provider-domain-id解码成iCloudDriverFileProvider/…，而且bird，cloudd，fileproviderd都在运行。
然后检查到，失败构建的窗口之内，iCloud日志记录如下：

  • 10:37:10 开始上传200个文档
  • 10:37:12 收到20个远端变更并且大量apply-changes
  • 原来的target在10:37:14创建
  • 10:37:25出现 upload progress…not tracked和 UNREACHABLE…should be needs-upload
  • 10:41:56又收到12个编辑和15个删除文件并执行apply-changes
    然后原来的Failsafe报告从正常应有的17个文件减少到3个，恰好消失了14个，target/failsafe-reports mtime/ctime也在构建结束之后继续变化。

然后检查了/private/tmp，同一份源代码，相同的Maven/Failsafe配置，相同的test order，连续3次 clean verify，三次都build success，而且源码哈希三轮都不变，所以排除Java/Spring/Failsafe/OpenAI SDK的嫌疑。

最后，这问题确认是iCloud同步工作目录干扰。修复就是原项目目录搬出iCloud Drive File Provider domain。

不确定写的咋样？

  2. 波尔布特段子，写的是「幻想自己被欣赏，实际现实可能完全不是那样」，人的自恋导致的灾难
  3. ubi段子，写的是「人在不知道自己骂什么的时候，先把安全网骂没，再发现自己正好掉下去了」，人自己的认知盲区导致的灾难
  4. 同性恋段子，写的是「制度套利」。（笑）。这个可以不局限同性恋，可以推到很多本来是照顾弱者的政策，被吐槽，被说不公平，然后吐槽的人看到有利可图，自己反而也去装弱者。歧视弱者和装弱者做制度套利之间，甚至根本不冲突。
