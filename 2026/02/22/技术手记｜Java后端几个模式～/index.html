技术手记｜Java后端几个模式～

发表于 2026-02-22 分类于 技术手记

今天我问ChatGPT，我之前写代码没思路，可能是对模式不了解？
GPT回我：要不要我给你几个模型？
于是这篇博客就有了。（笑）

今天（2026-02-22），我只记录模式，明天或者后天，我再补上实际的案例。

并发与一致性的常见模式

Check-Then-Act（先检查再执行）

典型场景：

  • 判断库存>0之后再扣减
  • 判断是否锁定再加锁
  • 判断是否存在再插入

问题：

  • 检查和执行分离，会被并发打穿

解决：

  • 原子操作（Lua）
  • 乐观锁
  • CAS
  • 数据库唯一索引

Lost Update（更新丢失）

典型场景

  • 两个线程读取同一值
  • 修改后覆盖

解决

  • 乐观锁 version
  • 行锁
  • CAS

Double Submit（重复提交）

典型

  • 用户点两次按钮
  • 重复下单

解决

  • 幂等 token
  • 唯一索引
  • 状态机控制

Cache Breakdown（缓存击穿）

典型

  • 热点Key过期
  • 同时大量请求打DB

解决

  • 互斥锁
  • 预热
  • 永不过期 + 异步刷新

Cache Penetration（缓存穿透）

典型

  • 查询不存在数据
  • 每次打DB

解决

  • 空值缓存
  • 布隆过滤器

Thundering Herd（惊群效应）

典型

  • 高峰期瞬间请求暴涨

解决

  • 限流
  • 排队
  • 削峰填谷

架构思维模式

Fail Fast（快速失败）

与其被慢慢拖死，不如：

  • 限流
  • 降级
  • 熔断

Graceful Degradation（优雅降级）

比如：

  • 评论系统挂了不影响主流程
  • 风控策略收紧

Idempotency（幂等性）

重复请求不影响结果

State Machine（状态机）

登录，订单，风控其实都可以用状态流控制
