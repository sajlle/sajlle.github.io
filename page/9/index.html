日常记录｜用AI学不懂的技术点，跟真人相比，区别是？

发表于 2026-03-12 分类于 日常记录 ， 技术手记

最近我找GPT给我讲MQ的用法，我其实培训班的时候，一直没弄明白怎么写一个最小demo。
培训班时期，我学的不咋样，很多基础概念都不懂。因为我只看培训班视频，没办法自己建立一个最小的可理解模型，或者培训班的课程，并没有足够优秀到可以让我快速建立一个最小最简单的可理解demo的程度。

我找GPT给我写一个最简单的MQ demo，只要写清楚怎么配置，生产者怎么发消息，消费者怎么消费消息即可。不要任何其他的拔高。
然后我运行完毕这个demo，我问它，路由key怎么匹配的？因为我不懂，生产者发消息的时候，怎么只写了交换机和路由key，消费者收消息的时候，怎么匹配到对应的队列上？
当然我讨厌它讲冗长的废话，直接给出三个例子，比如，我的交换机是v.exchange， 路由key是v.create，队列1是v.create，队列2是v.pay，队列和队列2都绑定了交换机v，那消费者怎么精确匹配到队列1而不是把消息扔到队列2？
这次它讲的开始像人了，讲，交换机会检查routing key == binding key？
我问：如果两个队列都绑定了同一个交换机，routing key 和 binding key都相等呢？
它：消息会投递到这两个队列。
我：那就是说，看消息是否投递到队列，第一看队列是否绑定了该交换机，第二看routing key和binding key是否一致？
它：对。

这个案例非常明确，AI跟真人教师之间的区别是，教师会掌握和评估学生的水准，也就是因材施教。
如果你要AI教你一个基础知识，你必须评估自己的水准，自己压缩信息，找盲点，否则你就会浪费很多时间被概念绕进去。

AI教我MQ的案例，跟培训班不同地方是：

  1. 培训班是直接视频教你怎么写（不讲原理，效率不如直接找AI帮你写个demo）
  2. 培训班的好处是会提前告诉你一点常见的坑点（但废话极其多，拓展极其少，有价值的细节塞在一堆令人无语的废话里）。
  3. AI会快速给你框架，但没有聚焦（不会针对你这人的情况聚焦，这也是目前AI无法替代真人教师的原因之一），从而也就无法针对性的压缩信息。

另，这可以延伸到写代码上：

  1. 自己会的部分，可以快速塞给AI，效率提升较快。
  2. 自己不懂的地方，先找AI问最佳实践框架，然后自己写个最佳实践的小demo，不懂的地方问AI。（因为AI强的地方是给通用框架，但它不懂什么细节会困住你，所以还是得自己弄个demo跑一跑，才知道困扰的地方）
  3. Demo搞定之后，再把技术塞对应的业务里。
  4. 问demo的时候，能用思考模型就用思考模型，思考模型相对的聚焦更强一些，我自己的体验是，GPT 5.3，不如GPT 5.4 Thinking会聚焦具体场景。

日常记录｜最近忙着写代码，好久没写随笔了，补上去～

发表于 2026-03-08 分类于 节点人生 ， 技术手记

好久没写随笔了，摘几段最近写的随笔

关于AI的创意写作

创意写作本身不仅仅关乎文字游戏，更关乎意图识别，知道用户要什么，现象建模，知道故事背后的隐喻，风格匹配，知道用什么风格达到用户的目标。
创意写作完全不是文字游戏，它拼的是对生活的建模和压缩，然后用策略性的表达展示这一点。

关于AI编程

AI不会收敛。虽然它能准确讲出哪个点错了。但它不会把经验压缩得足够简洁。
人理解之后，会对理解过的东西做压缩，这个压缩是个钩子，信息够抽象，而且很神奇地会自己匹配合适场景。

你能用 AI 编程的内容，永远是你已经理解的内容。
你用 AI 学习新内容，因为 AI 不会压缩，如果你也懒得理解，那就导致只学皮毛。

未来值钱的，是能验证 AI 是否做错的专家。

关于转行代码

没有哪个时候是完美的时机，完美的条件。
很多人总抱怨，要是早十年，转代码会很轻松。
但那个时候的人，也吐槽代码难写。
本质上这就是在找那个完美的条件，但我观察，完美的条件，就跟地平线一样，可望不可及。

很多人不是在等机会，他们是在等一个能让自己不用承担风险的机会。
不利因素存在，不等于人可以无限延期自己的路线。

职业稳定已经变成稀薄神话

教培曾经看着稳，后面也塌；
老师曾经是县城神职，现在也越来越挤；
体制内被很多人当宗教，但那不是我的宗教；
“找个稳定工作”这句老话，本身越来越像上个时代的回音。

与其为了一个根本不大现实的稳定幻想，吃很多苦，不如干自己喜欢干的职业。
反正上班就是找自己能吃的苦吃下去。

关于日常效率

一天也就 3～4 个小时是高效率时间，这段时间能干一天之内 85% 的任务。
其余时间，就是分神，看文档，折腾工具，改改 bug

绝不能轻忽饮食/环境的影响。
这是基本生存线保证。没有这一条，效率就无从谈起。

关于自己

我不确定自己是否进步，但缺乏外界反馈，我没有底。
但我真的超喜欢自己的状态。
我还是对自己很有信心的，扫清障碍，提高行动速度，我应该能进步得很快。

关于未来

我想过个几年，我也许会开自己的公司。
因为我：

  • 不喜欢被低效系统管着；
  • 很在意自由流动性；
  • 对结构、方法、效率、边界很敏感；
  • 对把经验抽象成模型这件事有兴趣；
  • 不只是想干活，还想理解“这活怎么组织才更合理”。

我不只想进入一个系统，然后活下去，还想这个系统能否被我重新搭建一下。

所以，「以后开公司」，对我来说不是发财梦，更像是一种延长线：

从现在的「我要活的自由」到未来的「我要定义组织形式」

关于爱情和工作的优先级

我一直觉得生存的基础就是工作，而爱情或者其他亲密关系，是生存之上的东西。
没了爱情，人可以活。但没了工作，下顿饭的着落就没了。

关于马年

马年，我喜欢，别人说是赤马红羊劫，我反而觉得，这是价值回归期。退潮了，才知道谁在裸泳。

技术手记｜AI会抢哪些人的饭碗？哪些技能在AI时代越来越稀缺？

发表于 2026-03-01 分类于 技术手记

这也是2月26日看论文的总结。当天我是5点睡觉，然后中午起来，傍晚18点吃完饭之后，我到三叔家看论文。
这篇也是arXiv上的论文，名字叫：Some Simple Economics of AGI。

论文观点我总结一下：

  1. AGI时代真正的瓶颈不是智能/执行，而是人类验证带宽。
  2. 经济分区从「例行/非例行」切换为「可测量/不可测量」，自动化会很便宜，但验证不可行的盲区会扩张。
  3. 过度部署会产生系统性外部性，未验证部署份额与失配叠加形成特洛伊木马外部性，表面指标/产出上涨，真实效用与控制力被掏空。
  4. 人类在环并不稳态：一方面初级岗位被吞掉，另一方面专家把经验写进数据加速自我淘汰，结果验证层既更重要，又更稀缺。
  5. 价值/护城河迁移：从产出能力迁移到可验证的真相，可追溯性，以及能承保的责任，并出现Liability-as-a-Service

其中几个点展开说：

  1. 生成接近0成本，越来越多人可以做出类似专业的作品，但这些作品到底行不行，需要验证。也就是说，生成不重要，验证生成才重要
  2. 越强的系统越会优化你给它的测量指标，导致指标越强，Goodhart 越快；验证越慢，漂移越隐蔽。
  3. Missing Junior Loop会是个很现实的问题。初级工作自动化，未来的专家从哪里来呢？专家少，组织会越来越依赖能背锅的老手，而老手又更快被消耗完。

对个人来说，需要做的转变是：

  1. 把自己定位成「意图导演 + 验证者」，而不是执行工具人，当智能变得廉价之后，人类的工作更可能迁移到意图，验证，承保。
  2. 用AI做合成练习，加速熟练度。但要注意验收，否则就是把自己训练成会产出但不会验收的人。

对组织的影响：

  1. 把验证当「生产技术」，不是合规成本：比如，可观测性、审计日志、回放、压测、灰度、事故复盘机制。
  2. 组织结构会自然走向「夹心」：需求/意图层更强、执行层自动化、验证与背锅层更稀缺——这会决定岗位价值与晋升路径。

技术手记｜最近看论文有感：用AI，而不是把脑子外包给AI

发表于 2026-03-01 分类于 技术手记

最近看arXiv上的文章，对比了用AI和不用AI的人，学习技能效果如何。自媒体把这个文章结论放大成，用AI会让你技能下降。
但实际更值得看的是：文章把AI组的使用方式分成6种persona，有的模式几乎不伤学习，有的模式直接把学习效果击穿。

论文里的高分模式有：

  1. Generation-Then-Comprehension：先生成，再追问理解 → 86%
  2. Hybrid Code-Explanation：要代码同时要解释 → 68%
  3. Conceptual Inquiry：只问概念，错误自己解决 → 65%

低分模式有：

  1. Iterative AI Debugging：反复让AI排障/验证（5–15问）→ 24%（最低）
  2. AI Delegation：只让AI写代码直接贴 → 39%
  3. Progressive AI Reliance：先问两句，后面逐步全交给AI → 35%

另，作者提到一点：debugging类提问占比越高，完成越慢、测验分越低。

看完论文，我总结了一下我用AI的方式如何避免陷入低分模式。

我这边的用AI学习的模式是：

  1. 问概念/框架/边界条件 -> 拿到信息地图（AI的作用是信息降噪）
  2. 我写最垃圾的demo -> 在摩擦里建模（自己捣鼓）
  3. AI review + 追问A/B取舍 -> 把建模压缩成可迁移规则（AI验证我盲点&给最佳实践模板）
  4. 我再改一轮 -> 完成「建模 -> 压缩 」的闭环（我照着最佳实践自己捣鼓）

如何判断啥时候，该自己捣鼓呢？

  1. 我说不清：这个模块的输入输出/失败模式
  2. 我不知道：这里为什么用A不用B
  3. 我能抄出来，但换个约束就不会改
    这时候AI最适合做：给关键词，给对比维度，给边界清单，给测试用例思路，而不是给最终实现

如何判断啥时候，可以照着最佳实践套模板

  1. 自己能写一个跑得通的「丑实现」
  2. 自己能解释关键取舍「哪怕不优雅」
  3. 能改约束并且重构「比如从单机限流 -> 分布式限流」
    这时候AI最适合做：review，重构建议，性能/安全/可观测性补强，替代方案对比

另，多瞎扯一句：其实非AI辅助的学习也类似，如果没有自己踩坑建模，直接被喂最优解，学习效果反而不如自己瞎捣鼓踩坑之后再看最优解效果好。

我以为家庭是利益共同体，实际我家是按照角色分配收益，按照能力分配责任

我一开始卖力干童工，以为家庭是利益共同体，但我家实际是按照角色分配收益，按照能力分配责任：

  • 利益&资源：按照角色分配，谁该被照顾，谁该忍，谁该背锅，都分配好角色了
  • 责任：按照能力分配，有能力=抗更多锅，弱的/闹的=责任更小，收益更大，资源被倾斜
  • 付出不产生谈判权：反而成了义务证据

这就出现一种悖论：我家里，越能干越吃亏，越讲道理越被甩锅。

我家是零和博弈，三叔家是非零和博弈

三叔家那边，是底线协议（非零和协议）

  • 女儿是外人也好，至少底线是不把她当耗材
  • 成绩不行 -> 允许身份置换（艺术）
  • 摩擦存在，但关系可维持：说明家里允许一定程度偏离模板

我家协议（零和）

  • 角色先分配：我被塞「能干，能忍，能顶」的位置
  • 角色按照资源走，责任按照能力走：越能干越该扛
  • 长期争吵不是偶然，是系统自洽，不反抗就被消耗，一反抗就被围剿

环境导致我跟堂姐的策略不同

所以我跟堂姐的策略就非常不同了：

  • 堂姐是变轨：跟家里有摩擦，但不断链，不退出，至少在人情场上，还演一下体面。对她来说，变轨收益高，因为她不撕破脸，也不会被拉回工具人&背锅位。
  • 我是跳轨：跟家里激烈摩擦，退出所有家务决策/不提供信息/不参与安排/不在人情场上演家庭和睦。对我来说，跳轨收益更高，因为不跳轨，只是变轨的话，依旧会被拉回工具人&背锅位。

总结：我们选择的策略不同，不单是个性使然，更像是在不同环境下，选择的最优博弈方式

简单总结：我是同辈孩子里，跳轨最激烈，跟家里摩擦最大的孩子，不是偶然，是我家的规则根本没给我留出口，跳轨是最优策略。否则我就会被拉回工具人位。

日常记录｜给我家做了一个结构画像，我家冲突激烈，不是偶然

发表于 2026-03-01 分类于 日常记录

强制度化童工化家庭的结构画像

系统定义

目标（表面）：

维持家庭生计，店面运转，家务效率，面子秩序

目标（真实）：

用“持续征用”制造可控性，稳定父母的焦虑与权威，降低对外部资源的依赖成本。

特征：

把孩子当作长期劳动力与情绪缓冲器，形成稳定排班机制（7–19岁、寒暑假、周末、全年执行）

输入

资源约束

  • 现金流紧张/不稳定（或者对不稳定高度恐惧）
  • 人手不足（或者不愿雇人/不信任外人/不想付出雇佣成本）

认知与价值观输入

  • 闲着 = 败家/变坏/不听话
  • 吃苦 = 正当性
  • 孩子是家庭资产/劳动力储备

情绪输入

  • 父母长期焦虑（钱/面子/亲戚比较/控制感不足）
  • 对不确定性低耐受 -> 需要立刻做点什么来「看见掌控」

环境触发器

  • 亲戚来访/面子局/装修/婚丧喜事/赶集旺季
  • 任何「外部变动」都会提升系统压力，从而增强对孩子的征用频率

核心规则

角色先分配

  • 我：可用/能干/该忍/该顶
  • 我的价值不是「发展」，而是「可调度性」

这导致：贡献越多，责任越多，但权限不增加。【很典型的反激励】

时间不属于我（属于父母）

  • 我的时间默认归家庭所有
  • 个人时间需要「批准/赏赐」，且可以被随时撤销

「劳动 = 服从」的绑定

  • 干活儿不仅是产出，更是服从验证
  • 让我帮忙是为了确认权威，我是否依旧可调度

无补偿机制

  • 别人家是「打一巴掌给一颗糖」
  • 我家是「打一巴掌再骂一顿」
    => 系统不给出口，不提供可恢复的情绪回路

甩锅协议

  • 建议者会被当作责任源头（我说一句 = 我该负责推进）
  • 承担者回被当作默认义务（我做一次 = 我该一直做）
    => 系统鼓励：「不承担的人永远更安全」

断章取义接口

  • 说话被截取成「可用于外部甩锅/内部指责」的片段
  • 语言不是用来协作，而是用来博弈与责任转移
    => 语言成为高风险输入源头

执行流

  1. 外部压力/内部焦虑上升
  2. 父母启动「控制回路」：寻找可被立刻调度的对象
  3. 选择最稳定可控资源 => 我
  4. 以道德语言封装指令
    • 你闲着干嘛
    • 一家人还计较
    • 你不干谁干
  5. 被拉进执行 -> 系统短期稳定（父母获得掌控感）
  6. 我试图协商/表达 -> 被判为「管太多/顶嘴」
  7. 系统通过争吵/羞辱/冷暴力把我压回可用状态
  8. 周期循环，直到我出现跳轨行为

输出（系统产物）

对父母

  • 即时掌控感（焦虑被转移）
  • 获得廉价劳动力与情绪泄压对象
  • 维持我在管家/我在当父母的叙事

对我

  • 极强的逆境执行力与工具理性
  • 对「被召唤/被打断」高度敏感
  • 需要确认安全边界才能投入个人事务
  • 对「解释/沟通」形成条件性恐惧（说话 = 被利用）

副作用

行为层

  • 形成「先做出成果才配休息」的逻辑
  • 容易进入「爆肝 -> 崩溃 -> 自责」循环
  • 对家庭事务产生全面回避（因为参与 = 被吸血）

情绪层

  • 休息羞耻感/闲置焦虑
  • 对亲密关系的「被征用恐惧」
  • 轻微的「反补偿冲动」：只要能自主，就想自主

关系层

  • 家庭沟通变零和博弈
    • 我赢了=他们输了
    • 我解释=我给接口
    • 我沉默=自保
  • 最终导向：退出式和平

系统的故障模式

自证预言（希腊神话模式）

父母为了防止独立而控制我
-> 控制过载
-> 我只能更激烈的跳轨独立
-> 父母说：「看吧，她就是要跑」
-> 控制更强（进一步加速分离）

反激励导致「能力惩罚」

我越是能干越被用，越被骂
-> 我的策略变成：不显能，不建议，不承担
-> 家庭效率更低，冲突更高
-> 父母更焦虑 -> 更想征用我（恶性循环）
