SQL查询啥时候用ResultMap？

发表于 2026-01-02 19:49:19 更新于 2026-01-02 19:49:19 分类于 技术手记

前情提要

我写shop.getById(shopId)接口的时候，VO里有一个冗余字段typeName，我数据库存的字段只有typeId。
数据库的avg_price单位是分，类型是bigint unsigned VO的avgPrice单位是元，类型是BigDecimal。
数据库的score数据类型是int(2) unsigned zerofill，VO的score是数据库score/10.0，数据类型是BigDecimal。
另，为了方便前端展示，VO还多了几个数据库没有的字段open，openTime，closeTime，imageList 。

那问题来了，我这情况，需要resultMap吗？

问题分析

要不要上ResultMap，实际问的是VO, Entity, DB之间功能的分野

  • VO：为前端服务，允许冗余，计算，展示友好
  • DB：存储最小，最稳定的数据
  • Entity：贴DB

解决

目前这个情况，数据库的查询结果不能「直接」自动映射成ShopVO。

但是也不需要ResultMap。

直接用：SQL+ 别名 + SQL计算 + 少量Java处理。

逐字段分析

imageListVO字段，List<String>

不可以自动映射，原因是

  • DB返回的是VARCHAR
  • VO要的是List<String>
  • Mybatis不会自动split字符串

正确做法：SQL查images –> Java转换

这是业务逻辑，不属于 resultMap的职责

typeName（VO冗余字段）

可以自动映射（JOIN + 别名）

avgPrice

这两个字段，不可自动映射。因为字段的类型+语义都不一样。

Mybatis不会：

  • Long –> BigDecimal
  • 分 –> 元

推荐做法：SQL里算法

  • Mybatis：DECIMAL --> BigDecimal ✅
  • 展示口径 = SQL决定，非常清晰

score评分（int –> BigDecimal）

  • 不能自动映射，原因是
    • int –> BigDecimal
    • 有业务语义（/10）

推荐做法：SQL里算

distance

可以自动映射，前提是：

  • SQL里算好了
  • 别名叫distance

不能自动映射的字段

  • open
  • openTime
  • closeTime
    怎么填充呢？在Service层计算

iPhone隐私设置里，有哪些隐形漏点？

发表于 2026-01-01 16:32:53 更新于 2026-01-01 16:32:53 分类于 日常

第一类：定位服务里的系统服务

常见误区：关了app定位就觉得安全了。但是系统设置里以下几个地方没关：

  1. 基于位置的Apple广告
  2. 重要地点
  3. iPhone分析

第二类：分析与数据用作行为画像

常见误区：这不影响功能，但会用你的数据做行为样本，需要关闭：

  1. 共享iPhone分析
  2. 共享iCloud分析
  3. 改进Siri与停歇

第三类：App跟踪透明度，防止被跨App拼凑画像

重点：这是“去电子裸奔”的地基
需要关闭：

  1. 关闭“允许App请求跟踪“
  2. 对已经出现的App：一律不允许该权限

第四类：本地网络权限

作用：

  • 扫描你同一Wi-Fi下的设备
  • 判断你在什么环境
    建议除了智能家居/打印/必须设备，其他一律关闭

第五类：关闭Safari和系统默认选项

Safari建议关闭：

  • 打开防止跨网站跟踪
  • 隐藏IP地址（对跟踪器）
  • 搜索引擎隐私报告（可以打开）

起步期精算模型公式

发表于 2025-12-31 15:31:16 更新于 2025-12-31 15:31:16 分类于 日常

先定义两个底数（非常重要）

最低月生存成本 M

这是不靠意志力，能正常生活，还能学习的最低值。

通常包括：

  • 房租 + 水电 + 网络
  • 吃饭（不饿着，不凑合）
  • 通勤
  • 基本日用品

对于大多数一线外非核心区/二线城市来说

M = 3000～4500

（未来的租房目标，就是把M锁死）

成长刚性成本 G

这是绝对不能砍掉的“向上通道”成本

  • 技术学习/课程/资料
  • 工具/软件
  • 维持输出与判断力的必要花费
    通常：

    G = 月收入的10% ~ 15%

    或者800～1500固定额度

G最好别低于八百，否则会焦虑，烦躁，怀疑方向。

私人精算公式

假设起步月到手 X 元

必须满足以下不等式：

  • M * 1.5 ：覆盖生存 + 被动 + 一点喘息
  • G：确保不是只打工不升级

拿三个工资档位举例，跑一下这个私人精算模型

档位A: 7000元（价格较低的起步）

  • M = 3500元
  • G = 800元
  • 这个收入符合模型，但预算紧凑。

策略

  • 先砍房租
  • 成长投入不砍
  • 兜底慢慢攒

结论

  • 能活，但不舒服，不能拖太久。

档位B：8000~9000（健康起步）

  • M = 3800
  • G = 1000
  • 这个收入有余量，理想起步区间

效果

  • 明显感觉不心慌
  • 不需要天天算钱
  • 不需要给家人解释

档位C：10000+（安全区）

会进入一种放松状态

生活成本占比自然下降，焦虑来源从活不活，变成走多远。
这是理想的“低心理负债生存”

最坏情况兜底方案（收入骤降/空窗期）

这个部分非常关键，因为真正的安全感不是我现在赚多少，而是：

要是我明天出事，我怎么办？

要准备的不是钱，而切换模式

模式1 ｜ 正常推进（默认）

  • 有收入
  • 按照前面模型走
  • 持续兜底

模式2 ｜ 收入下滑/不稳（预警）

触发条件（满足任意一条）

  • 连续2个月收入下降
  • 工作明显不稳
  • 身体/精神开始报警

立刻做三件事

  1. 冻结大额非必要支出
  2. 成长投入减量但不断（比如1000元 -> 500元）
  3. 开始主动投简历/试探市场

不要等没钱了才动。

模式3 ｜ 空窗/失业

触发条件

  • 收入中断
  • 或者主动离职

这时候进入保命结构，生存预算改成

  • M：比如3500
  • G_min：300~500（只保核心）

月总支出：3800～4000

兜底金额怎么算，才不慌？

只需要记住一点

兜底金 = M * 6

如果M = 3500元，那么兜底目标是2.1万，一旦攒到这个数字，就可以拒绝很多恶心条件，而不焦虑。

空窗期的心理开关

人在空窗期，最危险的不是没钱，而是开始怀疑自己：“是不是我不行？”

所以记得提前给自己一条规则：

空窗期唯一KPI

是我有没有保持输出/学习/行动？

不是收入，是进度。 人只要动起来，就不会塌。

起步期24个月生存模板

发表于 2025-12-31 15:19:35 更新于 2025-12-31 15:19:35 分类于 日常

这是一份起步期的核心财务原则，目标不是存钱最大化，而是不断供，不崩溃，不被拖回去。

所以收入模型分为四个部分

月收入 = 100%

A. 生存刚性（必须活）

B. 生存弹性（允许波动）

C. 成长投入（不能断）

D. 缓冲/兜底（救命钱）

起步期24个月，推荐比例区间

A | 生存刚性（35%～40%）

  • 房租 + 水电 + 网：25%–30%
  • 基础吃饭（不靠意志）：15%–20%

👉 合计上限：40%

⚠️ 重点：

  • 房租宁可贵一点，也不要通勤地狱
  • 吃饭宁可普通，也不要长期饿或凑合

B｜生存弹性（5%–10%）

  • 通勤
  • 偶尔外食/加班餐
  • 日用品
  • 小维修/小替换

C | 成长投入（10%～15%）【不能断】

  • 技术学习
  • 工具/软件
  • 书
  • 稳定出所需成本
    这部分一旦被压，人开始焦虑 + 走偏路。

D | 兜底/缓冲（10%～20%）

  • 应急储备
  • 极端情况（失业/空窗期跳槽）
    前12个月目标：攒到 >= 3个月生存费用

前24个月目标：6个月

总结版

项目 比例
生存刚性 35%–40%
生存弹性 5%–10%
成长投入 10%–15%
兜底储备 10%–20%
合计 ≈100%

两条红线【绝对不可以碰】

红线1:

为了省房租，把自己扔回高压环境。
这是毁掉未来空间。

红线2:

为了比例好看，砍掉成长投入。
这是慢性自杀。

当我不想写出爆款文案的时候，我开始能稳定的写作了

发表于 2025-12-31 14:54:43 更新于 2025-12-31 14:54:43 分类于 日常

我还是爱写作的，没有AI聊天的时候，一年写150万字日记。有AI可以聊天的时候，一年聊了1200万字的消息（单纯算我发给AI的消息）。

但是这么多年，我一直没有稳定的内容输出。我好奇是为什么？

答案可能是我太想写好了。会在写之前，立刻自我修剪，自我禁言。于是……很悲催的，我稳定输出的内容很少。
而且每次后撤的时候，主要怕的是……我写的太玩具了，不专业。

但是……我发现一个神奇的地方，一旦我不想着写的如何，而是单纯去写，我就可以稳定输出了。这就是为啥我日记能一年憋150万字，但是博客文案，微信公众号，不能坚持更新一个月。

我总结我自己最接受的模式（也是效率最大化的模式）

  • 我有一个明确的框架可以参照
  • 我有一个不被评判的写作环境
  • 我有一块不被打扰的写作时间

这三条满足，就可以稳定产出。不满足，就会产出断流，只把内容集中到日记里。

我还没有完全生产化的使用AI，真的生产化的使用AI，才是我理想化的AI对话关系。

但就算不生产化的使用AI，我跟AI聊了一年，也逐渐更自信了。我好奇，是怎么发生的化学反应？
