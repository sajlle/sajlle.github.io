日常记录｜4月，我从周口回到济源，一个人

发表于 2026-04-08 12:31:29 更新于 2026-04-08 12:31:29 分类于 日常记录

自从3月25日在周口西华逍遥镇跟父母夜里吵架，被妈威胁送精神病院，被爹拦住不许外出之后，我在过后的一周，一直做噩梦。
冲突发生两天左右，我开始做梦，梦到「我找父母要了10元钱，父母开始混合双打」。冲突发生4天左右，我梦到「妈追在我背后，打我」。
同时，现实里，我老家农村宅基地的房间，已经刷漆完毕，我父母要求「刷漆完毕之后立刻从三叔家搬进刚刷漆完毕的房间」。我不想让自己的肺当房间的人工甲醛净化机。
于是，在3月31日，我买票回了济源。

3月35日冲突细节，我再写一点。起因是我妈打呼噜太吵，我拍拍她的脸，说她打呼噜了。她说我打她的脸。她又打呼噜，我再拍她的脸，说她打呼噜，她说「我哪里打呼噜了？」。作势要打我。于是我立刻按住她。防止她真的打人。
后续她开始尖叫，喊我爹。
我爹赶过来，说我「你干嘛呢～大半夜的不让安生～」。
我妈：「我没打呼噜，她说我打呼噜～」
我：「你打了但不承认」
我爹：「不管怎么样，你不该按住你妈」
我：「不然让她打我嘛？」
我妈开始哭。开始数落我狼心狗肺（笑）

然后事情走向更奇妙了。
我妈忽然开始说：「你天天找我们要钱，我们都快养不起你了。整天买个这买个那～」
我：「我这月只找你要了50块买牛奶，其他的东西，肉，椅子都是我花自己钱买的」。
我妈：「好，那你以后不许要钱买吃的，你得跟我们一样，我们吃什么，你就吃什么」
我：「好，那你可以不追着我叨叨了吗？」

我妈又切攻击面：「你天天用卫生纸跟吃纸的一样～没用呢，纸就没了。你看后院厕所里的一堆。」
我：「你嫌弃我用的多，你为什么不定规矩？你只追着我说用的多，顶什么用？你说一周用几卷纸你不会追在我背后说？一卷？一卷的话，你总不至于天天在我背后叨叨了吧？」
我妈：「那你也不该用的浪费，你就不能节省点？」

我是在无语她的强词夺理。
我觉得很窒息，他们不可合作，不可沟通。不满意却不肯正面提出要求，也不协商，只一味的指责，我烦死了。
于是提出：「我要到院子里冷静一下」。

这话一出，我妈说「不行，你敢出去，我送你去精神病院」。
我爹忽然摁住我，说：「这大半夜的，你去哪里？」
我：「我就去院子里坐坐」
我爹：「不行」。
最后我不得不自扇耳光认错，他们才放我出去在隔壁厨房过夜。（笑）。

这晚过后，我开始出现莫名其妙紧张，在三叔家的卧室，会喘不过气，于是我把折叠椅放到三叔家的彩钢瓦棚子里，在房顶上写代码。我实在不想在那个幽暗的卧室里写代码了。至少三叔家的彩钢瓦棚子，是有出口的，是个半开放空间。开放空间里，我妈爹还像个人。（笑）

与此同时，家里的饭还是蛋白质极少，如果我不自己买点肉，找我爹要50块买一箱牛奶，单凭我妈爹的碳水大餐，我在老家很难撑下去写代码。

这件事我后来复盘，当时导火索未必是打呼噜事件，我想更多的是我妈对我买肉买牛奶而不给她分表示不满。所以我现在想，真正的导火索是我找我爹要的50块，刺激了她的神经。
所以后续她不停揪住我说「牛奶」「卫生纸」「天天买东西」这类跟直接冲突不相关的话。
所以这件事，表面上是我跟我妈打呼噜冲突，实际是我妈对我买牛奶不满，借题发挥。

但说实话，老家那点日均不到20克的蛋白质，不到50克菜，但极高碳水的饮食，我可能会吃坏身体。（因为我之前就一直很容易口渴，吃太多面条或者馒头之后，会特别快的犯困，更别说我还要写代码，打拳击，应付家里的高压冲突，这点饭根本顶不住日常消耗）。

3月30日，走之前，我舅舅来给我家排线，我在房顶写代码。我爹中午跟舅舅一起吃饭。剩了两个菜（羊肉小炒+辣椒腐竹）。我就只好吃两位的剩菜（笑）。就算是剩菜，也比我在家我妈给我做的饭好多了。
但一边吃我又觉得有种难以形容的感觉（笑）很「屈辱」的感觉。我找我爹要五十块买牛奶，结果被半夜妈爹双打，威胁送精神病院。但请舅舅吃饭，我爹可以请羊肉小炒，买啤酒，花80块。我妈当天买了香蕉和橘子，但悄悄拎到隔壁，没让我知道。我晚上去隔壁拿热水壶，才知道他们买了香蕉和橘子。

另，极为好笑的一个细节是：我妈因50块牛奶要送我去精神病院之后的一天，给她的一个亲戚转了30块，那个亲戚给她发微信「姐，没钱了，多少转点呗」（笑）

这些叠加起来，冲突，威胁送精神病院，不许外出，极其糟糕的饮食，极差的卫生（我在老家十几天都难洗澡，我妈半夜跟我睡一个房间，她一脱衣服，一股刺鼻的气味窜出来，我不得不借口上厕所，跑路到院子里躲避）。

正好我项目写完了，之前的面试资料在济源，我就跟妈爹说：「我去济源拿点面试资料，需要回去一趟」。
我爹：「你面什么职位？」言外之意是，如果是收益不高的岗位，他才懒得出钱呢。
我：「后端」

于是拖延了很久之后，我在3月31日，买票回了济源。
落地济源之后，我人松弛了很多。在西华逍遥镇的时候，我一直感到很有危机感。因为逍遥镇离西华县城有25公里。银行只有农行和农商行，工行/中行/建行/招行没见到过。没有电驴，没法骑车外出。钱/交通/公共空间都很紧张，我又因为在老家跟父母经常吵架，乃至于到了后期，两位直接威胁：「送你去精神病院」。于是对这种交通/钱/公共空间不足的地方，有种很深的危机感。
我感到危机的原因是，我不知道这个地方，我人身受到威胁，我有无机会报警？我有无机会在父母试图真的限制我的人身自由的时候，能快速打车或者快速通过公共交通离开风险点？

在济源，我跟父母冲突也有白热化的时候，比如吵上头了，但我在济源可以反锁房门，在有限的时间报警。或者我可以快速移动到公园（比如乘坐公交/打车，到公共空间，防止他们真的实施身体暴力）。
但在西华逍遥，这几乎办不到。一则是公共交通不发达，走镇里的公交，其实也就那么几班车，晚上几乎没有去县城的公交。二则，就算打滴，也难叫到滴。三则更别说晚上找个旅馆过夜或者找个吃饭的地方吃饭。
在逍遥的老家农村自建房，我家只有南边邻居房间是有人的。东西北都没有邻居。所以就算他们继续搞暴力，在缺乏见证者，我又难以报警的情况下，我认为这种情况对自己的人身安全非常不利。
还有一个糟糕的情况，我老家的农村自建房，房间门因装修被拆掉了，我甚至没有了锁门的机会。没有锁门的机会，我甚至没有机会报警。
最后，在老家的自建房，亲戚邻居都跟我父母是亲戚，老人多，就算有人会看，但也未必有人会制止，或者居中协调。

回到济源之后，大概连着两三晚上，我还是会噩梦。大概到了4月3日，我才开始恢复。这一切就像噩梦。

技术手记｜几个关于事务的思考

发表于 2026-03-29 10:24:05 更新于 2026-08-08 11:06:57 分类于 技术手记

事务生命周期的简单理解

  1. 执行状态
    • ACTIVE：事务正在执行中，还没提交
    • ROLLBACK-ONLY：事务正在执行中，但已经标记为只能回滚了
    • COMITTED/ROLLED BACK：事务已经提交或者回滚了
  2. 事务传播行为
    • 就是一个带事务的方法，调用另一个带事务的方法时，怎么相处。

关于事务传播行为 + 事务的使用场景

  1. REQUIRED:
    • 有事务就加入，没事务就新建
    • 适用场景：
      • 一个service下调用多个service子步骤
      • 这些子步骤必须作为一个整体提交或者回滚
    • 例子：
      • closeTimeoutOrder()里一起改订单状态，预定状态，库存，用户次数等。
    • 坑：如果内层REQUIRED方法把事务标记成了rollback-only，外层还想提交，就会报错UnexpectedRollbackException
  2. REQUIRES_NEW:
    • 不管有没有事务，都新建一个事务
    • 适用场景：
      • 需要独立提交或者回滚的操作
      • 例如：日志记录，审计等
      • 独立状态的留痕
    • 例子：
      • saveMqExceptionLog()，记录日志的事务不受业务事务的影响
      • savePaymentCallbackRawBody()，记录回调原始数据的事务不受业务事务的影响
      • 定时任务跑批失败时的明细记录
    • 坑：多占一个数据库连接，高并发下，外层事务还绑着连接，内层又再拿一个，连接池小了之后，可能会耗尽或者卡死。
  3. NESTED:
    • 外层有事务，就在同一个事务里savepoint，内层失败可以回滚到savepoint，不影响外层事务，外层没有事务，就新建一个事务。
    • 开箱即用：DataSourceTransactionManager 的 nestedTransactionAllowed 默认是 true，通常通过 JDBC Savepoint 实现 NESTED，前提是 JDBC 驱动/数据库支持 Savepoint。
    • 适用场景：
      • 需要局部失败不拖死整体
      • 确认底层事务管理器支持savepoint
      • 例子：
        • 不常见。
          坑： NESTED 有外层事务时，需要底层事务管理器支持嵌套事务，典型实现是 JDBC Savepoint。如果不支持，并不是自动退化成 REQUIRED，而通常会抛出 NestedTransactionNotSupportedException。4. SUPPORTS:
    • 有事务就加入，没事务就不用事务
    • 适用场景：
      • 查询类方法
      • 工具型读取逻辑
      • 不要求强事务语义，但如果上层已有事务，也愿意跟着走
    • 例子：
      • loadVoucherConfig()
      • queryReservationForDisplay()
    • 注意：它不是只读事务的同义词，只是可跟可不跟，跟只读的区别是，只读里面还有个read-Only。
  4. NOT_SUPPORTED:
    • 外面有事务，先挂起，自己非事务运行。
    • 适用场景：
      • 明确不想让某段代码被事务拖住
      • 大量纯查询，报表，非关键读取
      • 一些你不想继承上层锁范围/事务时长的逻辑
    • 例子
      • 大批量报表查询
      • 纯展示性聚合查询
  5. MANDATORY:
    • 外面必须有事务，没事务就抛异常
    • 适用场景：
      • 某个方法只能作为更大事务的一部分存在
      • 想强调约束方，防止别人单独乱调
    • 例子：
      • 某个只能在「统一结算事务」里调用库存调整步骤
  6. NEVER:
    • 外面有事务就抛异常，自己非事务运行
    • 适用场景：
      • 明确不想让某段代码被事务拖住

关于事务的坑

  1. 同类内部调用，事务注解可能失效，因为Spring的事务是基于AOP实现的，只有通过代理对象调用的方法才会被事务管理器拦截到。如果在同一个类内部直接调用另一个带有事务注解的方法，这个调用不会经过代理对象，因此事务注解不会生效。
  • 例子：

解决办法：

  • 将需要事务的方法提取到另一个类中，通过Spring注入调用。

另，不大推荐的：

  • 通过AOP代理对象调用方法，可以使用AopContext.currentProxy()获取当前代理对象，然后调用方法。
  1. 以为catch住异常就万事大吉
  • 事务默认只对RuntimeException及其子类进行回滚，如果catch住了异常，事务管理器就认为操作成功了，不会回滚。
  • 解决办法：
  • 在catch块里手动标记事务回滚，可以使用TransactionAspectSupport.currentTransactionStatus().setRollbackOnly();来标记当前事务为回滚状态。
  • 或者在@Transactional注解上指定回滚的异常类型，例如@Transactional(rollbackFor = Exception.class)，这样即使catch住了异常，事务也会回滚。

一些简单实践

  1. 业务逻辑中，尽量让事务边界清晰，避免过长的事务，减少锁竞争和资源占用。
  2. 对于需要独立提交的操作，使用REQUIRES_NEW，确保它们不受外层事务的影响。
  3. 对于查询类方法，使用SUPPORTS，既可以在事务中执行，也可以在非事务中执行，灵活适应不同场景。
  4. 注意事务传播行为的选择，确保它们符合业务需求，避免不必要的事务嵌套和资源浪费。
  5. 定期检查和优化事务的使用，确保它们的性能和可靠性，避免潜在的死锁和性能问题。

项目中的使用逻辑

主事务（REUQIRED）

  • 校验订单是否超时，状态是否关闭
  • 条件更新订单状态
  • 条件更新预定状态
  • 回滚库存
  • 回滚用户已抢购次数
  • 写一条关单成功明细
    注意：这些步骤放在主事务里，可以确保它们作为一个整体提交或者回滚，如果其中任何一步失败了，整个事务都会回滚，保证了数据的一致性和完整性。

独立事务（REQUIRES_NEW）

  • 异常日志
  • poision message/ 原始消息体
  • 审计失败明细
  • 定时任务失败记录
    注意：这些步骤放到独立事务里，可以确保它们不受主事务的影响，无论主事务成功还是失败，这些日志和记录都能独立提交，保证了数据的完整性和可靠性。

不需要进入事务

  • 查询候选超时订单列表
  • 打印日志
  • 组装返回对象
  • 非关键查询
    注意：这些步骤不需要进入事务，可以避免不必要的事务开销，提高性能和响应速度，同时也减少了锁竞争和资源占用。

简单总结

  • 失败必须撤销主流程的步骤，放在主事务里
  • 失败不需要撤销主流程的步骤，放在独立事务里
  • 不需要事务的步骤，直接执行，不进入事务
