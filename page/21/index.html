为啥遇到错误分支不直接return，而是throw？

发表于 2025-12-14 21:31:27 更新于 2025-12-14 21:31:27 分类于 技术手记

最近写项目，有点纠结，接口里走不通的分支，到底是return一个Result返回错误码，还是throw错误码回去？

后续还是选择throw，好处有几个：

  • return 错误码回去，后续别的service调用当前service，会需要不停写if(!res.success) return res这类代码，后续会变成嵌套地狱
  • 如果接口加了@Transactional注解，
    • 直接return Result.fail(...)，Spring认为这是正常返回，默认不会回滚。这会导致表1更新数据成功，表2更新失败，但还是返回成功，会导致表1记录已经写入，但表2数据没有同步更新，导致脏数据。像这类必须一致的操作，应该throw，配合事务回滚
    • throw BizException默认触发回滚。

最终做法：

  • 走不通的分支，throw BizException，传错误码，这样失败的分支可以直接冒泡，上层不接锅，统一由GlobalExceptionHandler兜底转换成Result.fail(...)。这样写一次handler可以少写无数个fail-return

村规宣讲的意外效果：妇女主任当众给 ChatGPT 做了场路演

“简单说，就是一种在手机上会跟你聊天、
比人还会说话，

“会聊天？比人会说话？

全场空气陡然一紧。

“但是——它会、会、会……

在“勾魂”两个字落下之前，
**“能帮孙子写作业”**这七个字已经深深刻进了几位大妈的心里。

“危险：是领导说的。

危险可以慢慢体会，

“反正有个新玩意儿，村里叫不要乱搞。”

但前排那位反应最快的大妈，
当晚就悄悄行动了。

她绕个弯走到巷子口，
把刚下班路过的李铁柱一把拽住——

‘在这个瞬息万变的时代里……’”

如何实现Mac和Windows投屏互通？

发表于 2025-12-06 20:53:23 更新于 2025-12-06 20:53:23 分类于 技术手记

问题

前几天，我实在难以忍受MacBook Pro的14寸小屏幕写代码得不停切窗口了。于是想着能不能把10寸的surface当副屏。
但是Surface跟Mac不互通，无法像投屏给ipad那样，直接一键投屏。

方案

于是我考虑以下方案：

  1. 上软件
    • duet display
    • ? screen
    • letsView
  2. 上硬件
    • 采集卡+HDMI转type-c线

各种方案的优缺点：

duet display

优点

  • 技术成熟，可以有线投屏，也可以无线投屏
  • 延迟低
  • 可以使用surface反向操作mac，不是单纯把surface当拓展屏幕
  • 可以多端互通，几乎涵盖了市面主流的操作系统，支持
    • 安卓
    • ios
    • ChromeBook
    • mac
    • win

缺点

  • 依赖网络
  • 需要注册软件账号
  • 需要付费

使用场景

  • 主屏副屏都要交互写作

Deskscreen

优点

  • 免费
  • 支持多端互通
  • 局域网镜像

缺点

  • 配置繁琐
  • 需要注册软件账号
  • 不支持无线
  • 延迟高
  • 不稳定

使用场景

  • 备选，不推荐

LetsView

优点

  • 免费
  • 跨平台

缺点

  • 延迟高
  • 模糊
  • 卡顿

使用场景

  • 临时查看PDF
  • 看图参考

采集卡+转接线

优点

  • 延迟极低
  • 不需要网络
  • 不需要注册账号

缺点

  • 只能把surface当拓展屏幕，不能用surface反向操控mac
  • 成本120元
  • 下单到能用，需要1～3天时间间隔

使用场景

  • surface 彻底当显示屏用

最后我还是选择duet display方案。放弃了采集卡+转接头路线。

如何操作duet display实现Mac和Surface互通？

  1. 注册duet display账号
  2. 选择套餐，我选的是duet display pro
  3. 下载软件到mac和surface
  4. 在mac和surface上分别登录该软件
  5. 准备一根双type-c数据线
  6. 把双type-c数据线两端接口分别插在mac和surface
  7. 等duet识别这两个设备，一般插线即可自动识别
  8. surface那边点击extend，mac这边点击connect
  9. 链接成功之后，把mac这边想要分屏的软件，点击移动到duet上
  10. 链接成功之后，在mac这边duet调节分辨率，帧率，模式。
  11. 然后就快乐的拿surface当二屏好啦～

duet display使用体验

优点

  1. 真的延迟低
  2. 操作方便，只需要一根双type-c数据线
  3. 即插即用
  4. 比较灵活，可以调整清晰度

缺点

  1. 用mac触控板，很难把鼠标箭头甩到surface分屏上，所以需要鼠标操作
  2. 偶尔会识别不到设备，通常是俩设备IP地址差距较大，或者一个设备挂了VPN，一个设备没有挂VPN
